# AI Capability Manifest 0.1: Field Dictionary

> Generated from `schema/0.1/capability.schema.json` by `npm run docs`. Do not edit by hand: change the schema and regenerate.

Metadata contract describing one independently adoptable AI capability (Mission 4, Manifest v0.1 draft, revised in place on 2026-10-23 from the Spikes 1-3 research). It describes a capability; it is not a runtime execution protocol, and it references native contracts (MCP, A2A, OpenAPI, SKILL.md) instead of restating them. Mission 4 owns this structure and its rules; the content of each manifest belongs to the capability's owners and the inventory owners. Only facts that every sampled source supplies are mandatory; the validator reports the completeness level a manifest reaches (x-completenessLevels) instead of requiring more. Omitted optional fields mean 'not provided' and null is never allowed; an explicit empty list means 'declared none'. Top-level fields prefixed with 'x-' are extension fields that core consumers ignore.

Schema `$id`: `https://schemas.example.com/ai-capability-manifest/0.1/capability.schema.json`

## Requirement levels

- **mandatory**: always required.
- **conditional**: required only when the stated condition holds.
- **optional**: may be omitted. Omission means "not provided"; consumers must not infer a value.

Top-level fields: 6 mandatory, 3 conditional, 23 optional.

## Completeness levels (proposed)

Read from `x-completenessLevels`. Levels are cumulative: a manifest reaches a level when it states the facts of that
level and of every level below it. A fact is stated when any of its fields has a value; an explicit empty list counts
(it declares none). The validator reports the level of every structurally valid manifest ('none' below the first
level) and enforces one only when asked (`validate --require-level <level>`).

| Level | Adds | Fields that state each fact |
|---|---|---|
| **discoverable** | It can be found and recognised: the mandatory fields, plus what it does and how it is used. | description: `description`; interface: `interfaces` |
| **assessable** | A reuse assessment can start: where it runs, its terms, its version, a lifecycle signal, and who owns or publishes it. Usually reachable from native metadata alone. | runtime: `runtime`; license: `license`; version: `capabilityVersion` or `publications[].nativeVersion` or `publications[].versionScheme`; lifecycle signal: `lifecycleStatus` or `source.status` or `source.updatedAt` or `publications[].status` or `publications[].updatedAt`; owner: `owner.name` |
| **adoptable** | A team can adopt it without asking: the setup it needs, how to reach its owner, and its limitations (an empty list declares none). Needs owner input. | setup: `setup`; owner contact: `owner.contact`; limitations: `limitations` |
| **governed** | A risk assessment is recorded: an assessed riskTier, which must cite its assessmentReference. Set by the governance owners (Mission 3), never inferred. | risk assessment: `riskTier` (not `unassessed`) |

## Conditional rules

| Applies to | When | Then required | Rule |
|---|---|---|---|
| manifest | `riskTier` is one of `low`, `medium`, `high` | `assessmentReference` | An assessed riskTier must cite the assessment that produced it, so that a tier cannot be self-asserted. |
| manifest | `lifecycleStatus` is one of `deprecated`, `retired` | `deprecation` | A deprecated or retired capability must record why, so that adopters can plan a migration. |
| manifest | `capabilityType` is `mcp_server` | `interfaces` | An mcp_server must declare at least one interface whose type is 'mcp'. |
| `source` | `source.type` is `repository` | `source.url` | A repository source must provide the repository URL. |
| `source` | `source.type` is `registry` | `source.registry`, `source.identifier` | A registry source must name the registry and the package identifier. |
| `source` | `source.type` is `provider` | `source.url` | A provider source must provide the provider's URL. |
| `source` | `source.type` is `other` | `source.description` | An 'other' source must describe how the capability is obtained. |
| `license` | `license.expression` is absent | `license.text` | A license must give an SPDX expression or the terms as text. |
| `interfaces[]` | `interfaces[].type` is one of `a2a`, `openapi` | `interfaces[].contractRef` | A2A and OpenAPI interfaces must reference their native contract (Agent Card or OpenAPI document) instead of re-describing it. |
| `costInformation` | `costInformation.model` is `other` | `costInformation.details` | An 'other' cost model must be explained in details. |
| `relations[]` | `relations[].id` is absent | `relations[].locator` | A relation must identify its target by id or by locator. |
| `provenance[]` | `provenance[].method` is `derived` | `provenance[].basis` | A derived value must state its basis, so that heuristic values can be told apart from values that follow from a documented convention. |

## Lifecycle states and transitions (proposed)

Read from `x-lifecycleTransitions` on `lifecycleStatus`. A state may always stay unchanged.

## Extension fields

Top-level fields matching `^x-[A-Za-z0-9][A-Za-z0-9._-]*$` are extension fields: accepted without validation and ignored by core consumers. Any other unknown field is an error.
